# 繁體中文技術文件寫作規範

## 概述

寫 API 文件、README 或涉及金額時，另外讀 `references/templates.md`。

繁體中文技術文件最常見的問題不是內容不夠，而是**讀起來卡卡的**：中英文擠在一起沒有空格、全形半形混用、翻譯腔一堆。本技能提供一套完整的繁體中文技術文件寫作規範，讓你的文件**專業、好讀、自然順暢**。

**核心原則：** 排版服務於閱讀體驗，規範服務於一致性，內容服務於讀者。

**參考標準：** [中文文案排版指北](https://github.com/sparanoid/chinese-copywriting-guidelines)

## 中文排版規範

### 空格

**中英文之間加空格：**

```
# 好
使用 Git 進行版本管理，搭配 Jenkins 實現持續整合。

# 壞
使用Git進行版本管理，搭配Jenkins實現持續整合。
```

**中文與數字之間加空格：**

```
# 好
本次更新包含 3 個新功能和 12 個 Bug 修復。

# 壞
本次更新包含3個新功能和12個Bug修復。
```

**數字與單位之間加空格：**

```
# 好
檔案大小不超過 5 MB，回應時間控制在 200 ms 以內。

# 壞
檔案大小不超過5MB，回應時間控制在200ms以內。
```

**例外：度數、百分比等不加空格：**

```
# 好
今天氣溫 32°C，CPU 使用率 95%。

# 壞
今天氣溫 32 °C，CPU 使用率 95 %。
```

**連結前後加空格：**

```
# 好
請參考 [官方文件](https://example.com) 取得更多資訊。

# 壞
請參考[官方文件](https://example.com)取得更多資訊。
```

### 標點符號

**中文語境使用全形標點：**

```
# 好
注意：該介面需要驗證，請先取得 Token。

# 壞
注意:該介面需要驗證,請先取得 Token.
```

**全形標點與英文／數字之間不加空格：**

```
# 好
專案使用 MIT 授權，詳見 LICENSE 檔案。

# 壞
專案使用 MIT 授權 ，詳見 LICENSE 檔案 。
```

**括號的使用：**

```
# 中文語境用全形括號
請執行安裝指令（詳見下方說明）。

# 括號內有英文或數字時用半形括號
該專案基於 Spring Boot (v3.2.0) 開發。

# 純英文內容用半形括號
See the documentation (README.md) for details.
```

**引號的使用：**

```
# 中文使用直角引號（推薦）
「確定」按鈕觸發表單送出，「取消」按鈕關閉彈窗。

# 嵌套引號
他說：「請點擊『確定』按鈕。」
```

### 數字

```
# 阿拉伯數字（技術文件中統一使用半形數字）
支援最多 100 個同時連線。

# 不要用中文數字寫技術參數
# 壞：支援最多一百個同時連線。

# 數字使用半形字元
版本號 v2.1.0，連接埠號 8080，HTTP 狀態碼 200。
```

## 中英混排最佳實踐

### 術語處理原則

**保留英文的情況：**

- 專有名詞：React、Kubernetes、Redis、MySQL
- 業界通用縮寫：API、SDK、CLI、ORM、CI/CD
- 指令和程式碼：`npm install`、`git commit`
- 協定和標準：HTTP、TCP/IP、JSON、REST
- 沒有公認中文譯名的術語：debounce、throttle、middleware、cache

**翻譯為中文的情況：**

- 有公認譯名的通用概念：資料庫、伺服器、瀏覽器、框架
- 描述性詞組：version control → 版本控制，load balancing → 負載平衡
- 文件標題和章節名稱（盡量使用中文，技術名詞可保留英文）

### 首次出現標註譯名

技術術語首次出現時，標註中英對照：

```
# 好
本系統採用訊息佇列（Message Queue）實現非同步通訊，
並使用死信佇列（Dead Letter Queue）處理失敗的訊息。

# 後續出現直接使用
訊息佇列的 Consumer 需要實現冪等性……
```

### 避免過度翻譯

台灣工程圈習慣直接使用英文術語，強行翻譯反而造成溝通障礙：

```
# 好：保留業界通用英文術語
在 Controller 層做參數驗證，Service 層處理商業邏輯。

# 壞：強行翻譯反而看不懂
在控制器層做參數驗證，服務層處理商業邏輯。

# 好
使用 Redis 做 Session 快取。

# 壞
使用「遠端字典服務」做「工作階段」快取。
```

## 兩岸用語

寫給台灣讀者，一律用台灣用語。模型很容易混進中國大陸用語，寫完要掃一次。

| 台灣 | 不要寫成 |
|---|---|
| 軟體、硬體 | 軟件、硬件 |
| 程式、程式碼 | 程序、代碼 |
| 資料、資料庫 | 數據、數據庫 |
| 網路 | 網絡 |
| 檔案、資料夾 | 文件、文件夾 |
| 預設 | 默認 |
| 設定 | 設置 |
| 介面 | 接口（指 UI 時）、界面 |
| 伺服器 | 服務器 |
| 記憶體 | 內存 |
| 支援 | 支持（指功能支援時） |
| 品質 | 質量 |
| 影片 | 視頻 |
| 部落格 | 博客 |
| 使用者 | 用戶（一般文件中） |
| 登入、登出 | 登錄、退出 |
| 執行 | 運行 |
| 同時、並行 | 並發 |
| 處理（訊息） | 消費（訊息） |
| 範本 | 模板 |
| 最佳化 | 優化（可接受，但正式文件用最佳化） |
| 透過 | 通過（表示「經由」時） |

## AI 腔

模型寫中文常有固定口癖，讀起來像機器寫的。以下一律刪掉或改寫：

- **空話開場與收尾**：「值得注意的是」「總的來說」「綜上所述」「讓我們來看看」「希望這對你有幫助」
- **大陸職場流行語**：賦能、抓手、打通、閉環、顆粒度、落地、對齊（指「取得共識」以外的用法）、沉澱、鏈路
- **假強調**：每段都加粗、到處用「非常」「極其」「至關重要」
- **破折號**：用「——」接補充說明。改用逗號、冒號、括號，或拆成兩句
- **「不是 X，而是 Y」**：沒有真的要反駁 X 時不要用
- **emoji 當段落標記**

## 寫給使用者的回覆

對話回覆、提問卡、成果報告這類直接給使用者看的文字，再加三條：

- **結論先講**：第一句就是結果或要使用者做的事
- **完整句子**：不用電報體或箭頭串起來的片段，一句只說一件事
- **數字標來源**：說明是自己量的、讀檔案得到的，還是推測的

## 常見問題與避坑指南

### 問題一：翻譯腔

**特徵：** 句式生硬、不符合中文表達習慣。

```
# 翻譯腔
這個函式被用來計算使用者的折扣。如果你想要取得更多資訊，請參考文件。

# 自然中文
這個函式用於計算使用者折扣。更多資訊請參考文件。
```

**要點：**
- 避免被動語態（「被用來」→「用於」）
- 避免冗餘代詞（「你想要」→ 直接說）
- 避免直譯英文句式

### 問題二：句式歐化

**特徵：** 長定語、多重從句、一句話說不完。

```
# 歐化句式
這是一個可以幫助開發者在不需要手動設定複雜的建置工具鏈的情況下
快速搭建現代化前端專案的腳手架工具。

# 正常中文
這是一個前端 scaffold 工具，幫助開發者快速建立專案，省去手動設定建置工具鏈的麻煩。
```

**要點：**
- 長句拆成短句
- 把定語從句改成並列句
- 一句話只說一件事

### 問題三：過度翻譯

```
# 過度翻譯
請開啟您的「終端模擬器」，執行「節點套件管理器」的安裝指令。

# 正常寫法
請開啟終端機，執行 npm install。
```

### 問題四：中英標點混用

```
# 壞：中文句子用了英文逗號和句號
請先安裝相依套件,然後執行測試.

# 好：中文句子用全形標點
請先安裝相依套件，然後執行測試。

# 壞：英文內容用了中文標點
Run `npm install`，then `npm test`。

# 好：英文內容用半形標點
Run `npm install`, then `npm test`.
```

### 問題五：缺乏結構化

```
# 壞：一大段文字沒有分段
本系統使用 Redis 做快取以提升查詢效能，同時使用 MySQL 做持久化儲存
寫入時先寫 MySQL 再非同步更新 Redis 讀取時先查 Redis 若未命中再查
MySQL 並將結果寫回快取，過期時間設為 30 分鐘……

# 好：用清單和分段整理資訊
本系統的快取策略如下：

- **儲存層：** MySQL（持久化）+ Redis（快取）
- **寫入流程：** 先寫 MySQL，再非同步更新 Redis
- **讀取流程：** 先查 Redis → 未命中則查 MySQL → 寫回 Redis
- **快取過期：** TTL 設為 30 分鐘
```

## 寫作檢查清單

發布文件前，逐項確認：

### 排版

- [ ] 中英文之間有空格
- [ ] 中文與數字之間有空格
- [ ] 中文語境使用全形標點
- [ ] 英文／程式碼部分使用半形標點
- [ ] 沒有全形半形標點混用

### 術語

- [ ] 專有名詞保留英文原文
- [ ] 首次出現的術語標註了中英對照
- [ ] 沒有過度翻譯業界通用術語
- [ ] 術語前後使用一致

### 內容

- [ ] 句子簡短，沒有歐化長句
- [ ] 沒有不必要的被動語態
- [ ] 用清單和表格整理結構化資訊
- [ ] 程式碼範例可以直接執行
- [ ] 沒有翻譯腔

### 用語與語氣

- [ ] 沒有中國大陸用語（見「兩岸用語」）
- [ ] 沒有 AI 腔（見「AI 腔」）

### 格式

- [ ] 標題層級正確（不跳級）
- [ ] 程式碼區塊標註了語言類型
- [ ] 連結可以正常存取
- [ ] 圖片有 alt 文字
